# 🔌 คู่มือวิศวกรรมฮาร์ดแวร์และการต่อวงจร (Hardware & Wiring Guide)

เอกสารนี้อธิบายรายละเอียดเชิงลึกเกี่ยวกับพิน (Pinout), บัสการสื่อสาร (SPI vs I2C), การจัดการแรงดันไฟฟ้า และการแก้ปัญหาฮาร์ดแวร์สำหรับโปรเจกต์ **ESP32 + RFID RC522 + OLED SSD1306**

---

## 1. ผังการจัดสรรขาพินของ ESP32 (Pin Allocation Architecture)

บอร์ด ESP32 มีบัสฮาร์ดแวร์แยกกันระหว่าง **I2C** และ **VSPI (SPI มาตรฐาน)** ซึ่งช่วยให้เครื่องอ่านบัตรและหน้าจอสามารถทำงานพร้อมกันได้โดยไม่แย่งแบนด์วิดท์กัน:

```
                          ┌──────────────────────────┐
                          │       ESP32 DEVKIT       │
                          │                          │
   [จอ OLED I2C]          │                          │   [RFID RC522 SPI]
   SDA (Data)   ─────────►│ GPIO 21          GPIO 19 │◄──────── MISO (Data In)
   SCL (Clock)  ─────────►│ GPIO 22          GPIO 23 │◄──────── MOSI (Data Out)
                          │                  GPIO 18 │◄──────── SCK  (Clock)
                          │                  GPIO 5  │◄──────── SS/SDA (Chip Select)
                          │                  GPIO 4  │◄──────── RST  (Reset Pin)
                          │                          │
   [ระบบเสียงและไฟ]       │                          │
   Buzzer       ─────────►│ GPIO 25                  │
   LED สีเขียว  ─────────►│ GPIO 26                  │
   LED สีแดง    ─────────►│ GPIO 27                  │
                          │                          │
   แหล่งจ่ายไฟ            │                          │
   3.3V Rail    ─────────►│ 3V3                      │
   Ground Rail  ─────────►│ GND                      │
                          └──────────────────────────┘
```

---

## 2. ทำไมต้องย้ายขา RST ของ RC522 มาที่ GPIO 4?

ในบอร์ด ESP32 ขาเริ่มต้นของบัส **I2C คือ GPIO 21 (SDA) และ GPIO 22 (SCL)**:
* บอร์ดรุ่นทั่วไปหลายตัวอย่างมักจะต่อขา Reset (RST) ของโมดูล RC522 เข้าที่ GPIO 22
* แต่ในโปรเจกต์นี้ เรามีการเพิ่ม **จอแสดงผล OLED เข้ามาทางบัส I2C** ซึ่งต้องใช้ขา GPIO 22 เป็นสัญญาณนาฬิกา (SCL)
* หากปล่อยให้ต่อที่ GPIO 22 ทั้งคู่ สัญญาณนาฬิกาของจอ OLED จะไปกระตุ้นขา Reset ของชิป RFID ตลอดเวลา ทำให้เครื่องอ่าน RFID ค้างและไม่สามารถอ่านบัตรได้เลย!
* **แนวทางแก้ไข:** เราจึงย้ายขา RST ของโมดูล RC522 ไปต่อที่ **GPIO 4** แทนอย่างถาวร ทำให้ทั้งสองอุปกรณ์ทำงานร่วมกันได้อย่างราบรื่น 100%

## 3. กฎเหล็กเรื่องแรงดันไฟฟ้า (Power Voltage Rules)

> [!CAUTION]
> **โมดูล RC522 รองรับแรงดันไฟสูงสุดเพียง 3.3V เท่านั้น!**
> * ห้ามนำขา VCC ของ RC522 ไปต่อเข้ากับขา **VIN หรือ 5V** ของ ESP32 เด็ดขาด
> * แม้ว่าตัวโมดูลบางรุ่นอาจจะไม่พังทันที แต่ชิปจะร้อนจัดและหยุดการส่งคลื่นวิทยุ 13.56 MHz ทำให้แตะบัตรไม่ติด หรือชิปไหม้เสียหายถาวร
> * จอแสดงผล OLED 0.96 นิ้ว สามารถต่อเข้าขา 3.3V ได้เช่นกัน

## 4. แผนภาพการต่อสายวงจรบน Breadboard

```
[ESP32]             [อุปกรณ์ภายนอก]
3V3   ────────────> แถบไฟบวก (+) ของ Breadboard (3.3V)
GND   ────────────> แถบกราวด์ (-) ของ Breadboard (GND)

OLED VCC  ────────> แถบ 3.3V (+)
OLED GND  ────────> แถบ GND (-)
OLED SCL  ────────> ESP32 GPIO 22
OLED SDA  ────────> ESP32 GPIO 21

RC522 3.3V ───────> แถบ 3.3V (+)
RC522 GND  ───────> แถบ GND (-)
RC522 RST  ───────> ESP32 GPIO 4
RC522 SCK  ───────> ESP32 GPIO 18
RC522 MISO ───────> ESP32 GPIO 19
RC522 MOSI ───────> ESP32 GPIO 23
RC522 SDA  ───────> ESP32 GPIO 5

Buzzer (+) ───────> ESP32 GPIO 25
Buzzer (-) ───────> แถบ GND (-)

LED เขียว (+) ────> ตัวต้านทาน 220Ω ────> ESP32 GPIO 26
LED เขียว (-) ────> แถบ GND (-)

LED แดง (+) ──────> ตัวต้านทาน 220Ω ────> ESP32 GPIO 27
LED แดง (-) ──────> แถบ GND (-)
```

## 5. ตารางตรวจสอบความพร้อมของฮาร์ดแวร์ (Pre-flight Checklist)

ก่อนเสียบสาย USB จ่ายไฟเข้าบอร์ด ให้ตรวจสอบ 4 ข้อนี้:
1. [ ] ขา VCC ของ RC522 ต่อเข้ากับ **3.3V** (ไม่ได้ต่อ 5V)
2. [ ] ขา RST ของ RC522 ต่อเข้ากับ **GPIO 4** (ไม่ได้ต่อ GPIO 22)
3. [ ] ขา SDA ของจอ OLED ต่อที่ **GPIO 21** และ SCL ต่อที่ **GPIO 22**
4. [ ] ตัวต้านทาน 220Ω ถูกต่ออนุกรมกับหลอด LED ทั้งสองหลอดเพื่อจำกัดกระแสไฟ
